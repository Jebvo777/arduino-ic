# Пошаговый импорт

1. Распакуйте FULL на своем Windows-компьютере в папку `full`. Внутри должны находиться пути старого сайта, например `full/search/img/aleksnet_document/...`.
2. Из отдельного комплекта импорта возьмите `catalog.csv`. Если есть `embedded-media.zip`, распакуйте его **внутрь full**; получится `full/mik-embedded/...`.
3. В WordPress → MIK Shop → Импорт загрузите CSV. Файл передаётся фрагментами, поэтому upload_max_filesize не обязан вмещать весь CSV.
4. Укажите предел одного пакета в МБ. Для начала удобно 50 МБ. Алгоритм оставляет запас под ZIP и ограничивает пакет 500 товарами. Один товар с его файлами не делится между пакетами. Если он превышает выбранный лимит, нужен больший лимит и новый план.
5. Дождитесь расчёта. Страница остаётся открытой, прогресс обновляется AJAX. При закрытии страницы можно выбрать тот же импорт и продолжить планирование.
6. По умолчанию выбраны все пакеты. Для пробы снимите лишние отметки, сохраните выбор и скачайте BAT. Выбор можно изменить позже.
7. Положите BAT рядом с папкой full. Запустите. Нужен стандартный Windows PowerShell 5.1 или новее. Если full не найдена, скрипт попросит путь. Дополнительные программы и 7-Zip не нужны.
8. BAT создаёт папку `mik-packages-ID` и ZIP с точными именами из плана. Он читает только нужные изображения/PDF и не включает PHP, SQL, пароли или весь старый сайт. Общий файл может попасть в несколько независимых пакетов.
9. Просмотрите `missing-files.txt`. Отсутствующие файлы не заменяются выдуманными изображениями; товары без них всё равно импортируются, с предупреждением в журнале.
10. Загрузите один ZIP и нажмите «Загрузить и импортировать». Каждая строка обрабатывается коротким запросом, не перезагружая страницу. После завершения отобразится имя следующего выбранного пакета. Можно остановиться после текущего запроса и продолжить позже.

Пакеты загружаются фрагментами до 1 МБ; от размера целого архива зависит место на диске и лимиты хостинга, но не лимит одного HTTP-запроса. CSV не должен превышать 100 МБ, ZIP — 1 ГБ. Для загрузки и распаковки должен оставаться свободный диск. Не удаляйте временные файлы PHP, пока импорт не завершён.

Медиа проверяются по расширению, реальному типу и SHA-256; проверяются пути ZIP, размер распаковки и принадлежность пакета плану. Товары обновляются по legacy_id/SKU. Файлы с одинаковым SHA повторно используются. Изображения загружаются без генерации множества миниатюр, чтобы снизить нагрузку shared hosting.

## Формат каталога

UTF-8 с BOM, разделитель `;`, первая строка — технические имена колонок. Для файлов, массивов и характеристик используется JSON в CSV-ячейках.

- `legacy_id`, `sku`, `source_sku`, `name`, `category`, `brand`, `package`.
- `price_rub`, `price_wholesale`, `price_special`, `stock`, `stock_note`.
- `description`, `short_description`, `specs_json`.
- `images_json`, `pdfs_json`, `ozon_url`, `assets_json`, `source_url`.
- `new`, `featured`.

`assets_json` содержит объекты `{ "path": "search/img/...jpg", "size": 12345, "kind": "image" }`. Пути идут от корня full. `images_json` и `pdfs_json` перечисляют соответствующие пути. `specs_json` — массив `{ "label": "Напряжение", "value": "600", "unit": "В" }`; возможно поле `param_key` из справочника.

Базовая цена переносится в WooCommerce, оптовая — в группу МелкОпт (ID 3), спеццена сохраняется в метаполе `_mik_special_price` для последующей настройки коммерческих условий. Валютный прайс загружается отдельно; значения в долларах не вычисляются из рублёвых автоматически.

## Исходная выгрузка

`tools/prepare_catalog.py` читает XLSX, карту файлов и SQL как данные; SQL не выполняется. Скрипт не переносит клиентов, старые пароли, заказы или платёжные данные. Встроенные data URI извлекаются отдельно. Если основной путь отсутствует в карте, используется существующее изображение `d_` или `s_`. Все остальные отсутствующие пути перечислены в отчёте.

В некоторых исходных строках пустое наименование и нестандартно заполненные поля. Альтернативное имя используется с новым техническим SKU `legacy-ID`; исходные цены и остатки сохраняются, а такие строки перечисляются в `source-field-notes.json`. Их следует просмотреть перед продажами. Это исправление структуры, без догадок о правильной цене.

Подготовленные данные поставляются отдельным архивом здесь, а исходный код находится в GitHub. FULL не скачивался и не включался в плагин.
