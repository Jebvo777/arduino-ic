# Пошаговый импорт

1. Распакуйте FULL на своём Windows-компьютере в папку `full`. Внутри должны находиться пути старого сайта, например `full/search/img/aleksnet_document/...`.
2. Возьмите ранее выданный каталог CSV. Если есть `embedded-media.zip`, распакуйте его **внутрь full**; получится `full/mik-embedded/...`.
3. В WordPress → MIK Shop → Импорт товаров загрузите CSV с компьютера или по прямой публичной ссылке. Для существующего импорта CSV повторно загружать не нужно.
4. Укажите максимальный размер **одного ZIP**, например `800` МБ. Весь каталог попадёт в план; общий объём материалов не ограничивается этим числом. Размеры в таблице плана предварительные, поскольку исходная выгрузка могла устареть после конвертации изображений.
5. Дождитесь расчёта плана. При закрытии страницы выберите тот же импорт и продолжите расчёт. Отметьте все пакеты для полного импорта либо нужную часть для пробного.
6. Нажмите «Сохранить выбор и скачать BAT». После обновления плагина до 1.2.3 **скачайте новый BAT**, старый скрипт не умеет дополнительно делить файлы по их фактическим размерам.
7. Положите BAT рядом с папкой full и запустите. Нужен Windows PowerShell 5.1 или новее; дополнительные архиваторы не нужны. Если папка full не найдена, скрипт попросит её путь.
8. BAT найдёт изображения, в том числе с изменённым расширением, измерит реальные файлы, вычислит контрольные суммы и создаст ZIP-части до введённого размера. Превышение суммарного размера пакета создаёт дополнительные части. На каждом запуске создаётся отдельная папка `mik-packages-ID/build-дата-время-код`, её путь показывается в консоли.
9. В этой папке находятся ZIP, `upload-order.txt` с порядком загрузки, `missing-files.txt` с ненайденными файлами и `replaced-files.txt` с заменами расширений. Не смешивайте файлы разных сборок после изменения FULL.
10. Загружайте ZIP **из новой папки сборки** по списку. Пример: `mik-3-0001-part0001-of0003.zip`, затем part0002 и part0003. После первой части сайт покажет общее число частей и имя следующей. Доступны загрузка с компьютера и по прямой ссылке.
11. После приёма всех частей пакета начинается импорт товаров небольшими запросами без перезагрузки страницы. При паузе нажмите «Продолжить». Затем загружайте части следующего пакета.

На сайте хранятся отдельные ZIP-части; один большой ZIP из них не собирается. Медиа товара могут находиться в разных частях, привязки сохраняются. Нужны свободное место под части и итоговые медиа, а также сохранение временных файлов PHP до завершения импорта. Пакеты передаются с компьютера фрагментами до 1 МБ; весь CSV не должен превышать 100 МБ, отдельный ZIP — выбранный лимит и общий предел 1 ГБ.

Каждый готовый ZIP измеряется перед выдачей. При необходимости часть с несколькими файлами дробится ещё раз. Если один отдельный файл даже после ZIP-сжатия сам превышает выбранный предел, скрипт укажет его имя и размер: такой файл нужно уменьшить либо выбрать больший максимум ZIP. Последние части и сжатые архивы могут быть меньше лимита.

Медиа проверяются по реальному типу, путям и SHA-256. Комплект частей привязан к одному импорту, пакету и фактическим файлам. Товары обновляются по legacy_id/SKU. Файлы с одинаковым SHA повторно используются. Изображения загружаются без генерации множества миниатюр, чтобы снизить нагрузку shared hosting.

## Ошибка Actual files exceed… в старом BAT

Ошибка относилась к сумме реальных размеров файлов пакета, а не к лимиту загрузки хостинга. После конвертации PNG мог оказаться больше JPG из старой выгрузки. Версия 1.2.3 создаёт дополнительные ZIP-части автоматически. Установите обновление, скачайте новый BAT из того же плана, оставьте 800 МБ и пересоберите ZIP. Прежний CSV подходит.

## Старый путь JPG, а файл переконвертирован

Если CSV содержит `search/img/part.jpg`, а в FULL есть `search/img/part.png`, BAT сначала проверит точный путь, затем JPG, JPEG, JPE, PNG, WebP, GIF, AVIF, BMP, DIB, TIF, TIFF, ICO, HEIC и HEIF в той же папке с тем же именем без расширения. Регистр расширения Windows не влияет на поиск. При нескольких вариантах действует указанный порядок. PDF остаются отдельными документами.

В ZIP сохраняется настоящее имя, а соответствие со старым путём записывается в манифест и replaced-files.txt. Импортёр определяет MIME по содержимому. BMP, TIFF, ICO и HEIC/HEIF преобразуются в PNG при поддержке исходного формата редактором изображений хостинга. Если поддержки нет, журнал показывает найденное имя и причину; такой файл можно заранее сохранить в JPG, PNG или WebP.

Для повторного обновления уже завершённых пакетов создайте новый план через «Пересчитать пакеты», скачайте его BAT и соберите новые ZIP. Уже завершённые пакеты не импортируются повторно автоматически.

## Пересчёт плана после обновления до 1.2.1

Откройте прежний импорт, в поле «Максимум для одного ZIP, МБ» укажите `800` и нажмите «Пересчитать пакеты». Будет создан новый план для всего исходного CSV с выбранными по умолчанию всеми пакетами. BAT уточнит реальные размеры и количество ZIP-частей. CSV повторно загружать не нужно. Прежний план и уже созданные товары сохраняются.

Дождитесь окончания расчёта, скачайте **новый BAT** и сформируйте ZIP заново. Новые файлы лежат в папке с новым ID импорта; прежние ZIP относятся к прежнему плану. При полном импорте оставьте отмеченными все пакеты. В лимит входит каждый отдельный ZIP, общего лимита на сумму пакетов нет.

В пакетах находятся изображения и PDF, на которые ссылается CSV. Размер каталога и его файлов не обязан совпадать с размером FULL, где есть также код старого сайта и другие не связанные с товарами файлы.

## Загрузка по ссылке

Вставляйте прямую HTTP(S)-ссылку, по которой файл скачивается без входа в аккаунт. Страница просмотра облачного диска или HTML-страница вместо файла будет отклонена. Для ZIP используется пакет, сформированный BAT выбранного импорта: произвольный архив FULL не подходит.

Скачивание выполняет сервер сайта, файл не проходит через браузер. Источники с поддержкой HTTP Range скачиваются частями с сохранением смещения; при перерыве выберите «Продолжить скачивание». Без Range используется потоковое скачивание целого файла. Если источник не успевает отдать такой файл за время запроса хостинга, используйте загрузку с компьютера или другую прямую ссылку с поддержкой Range. Исходящим HTTP-запросам хостинга должен быть разрешён доступ к источнику.

Кнопка «Пауза» завершает текущий запрос и сохраняет достигнутый прогресс. Для локального файла повторно выберите тот же файл и нажмите загрузку; для ссылки используйте «Продолжить скачивание». Кнопка «Сбросить скачивание» удаляет незавершённый временный файл по ссылке.

## Если загрузка останавливалась после 1 МБ

Обновите плагин до 1.2.0, очистите кеш объединённых JS/CSS при его использовании, откройте страницу MIK Shop заново с Ctrl+F5 и повторно выберите тот же CSV. Изменять каталог или увеличивать лимит 999 МБ не требуется. В старой версии строковое значение размера фрагмента складывалось со смещением как текст, и следующий запрос превышал внутренний лимит фрагмента. Теперь размер нормализуется как число, а позицию подтверждает сервер. Повторная отправка уже полученного фрагмента не дописывает его в файл второй раз.

## Формат каталога

UTF-8 с BOM, разделитель `;`, первая строка — технические имена колонок. Для файлов, массивов и характеристик используется JSON в CSV-ячейках.

- `legacy_id`, `sku`, `source_sku`, `name`, `category`, `brand`, `package`.
- `price_rub`, `price_wholesale`, `price_special`, `stock`, `stock_note`.
- `description`, `short_description`, `specs_json`.
- `images_json`, `pdfs_json`, `ozon_url`, `assets_json`, `source_url`.
- `new`, `featured`.

`assets_json` содержит объекты `{ "path": "search/img/...jpg", "size": 12345, "kind": "image" }`. Пути идут от корня full. `images_json` и `pdfs_json` перечисляют соответствующие пути. `specs_json` — массив `{ "label": "Напряжение", "value": "600", "unit": "В" }`; возможно поле `param_key` из справочника.

Базовая цена переносится в WooCommerce, оптовая — в группу МелкОпт (ID 3), спеццена сохраняется в метаполе `_mik_special_price` для последующей настройки коммерческих условий. Валютный прайс загружается отдельно; значения в долларах не вычисляются из рублёвых автоматически.

## Исходная выгрузка

`tools/prepare_catalog.py` читает XLSX, карту файлов и SQL как данные; SQL не выполняется. Скрипт не переносит клиентов, старые пароли, заказы или платёжные данные. Встроенные data URI извлекаются отдельно. Если основной путь отсутствует в карте, используется существующее изображение `d_` или `s_`. Все остальные отсутствующие пути перечислены в отчёте.

В некоторых исходных строках пустое наименование и нестандартно заполненные поля. Альтернативное имя используется с новым техническим SKU `legacy-ID`; исходные цены и остатки сохраняются, а такие строки перечисляются в `source-field-notes.json`. Их следует просмотреть перед продажами. Это исправление структуры, без догадок о правильной цене.

Подготовленные данные поставляются отдельным архивом здесь, а исходный код находится в GitHub. FULL не скачивался и не включался в плагин.
