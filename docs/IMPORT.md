# Пошаговый импорт

1. Распакуйте FULL на Windows-компьютере в папку `full`. Внутри должны находиться пути старого сайта, например `full/search/img/aleksnet_document/...`.
2. Возьмите ранее выданный каталог CSV. Если есть `embedded-media.zip`, распакуйте его **внутрь full**; получится `full/mik-embedded/...`.
3. В WordPress → MIK Shop → Импорт товаров загрузите CSV с компьютера или по прямой ссылке. В существующем импорте CSV повторно загружать не нужно.
4. Укажите **ориентировочный размер ZIP**, например `800` МБ. Это значение используется для предварительного распределения по старым размерам CSV; фактический ZIP может получиться 900 МБ или больше. Общий объём каталога не ограничивается этим значением.
5. Дождитесь расчёта. Выберите все пакеты для полного импорта или часть для пробного. На каждый отмеченный пакет BAT создаст ровно один ZIP с именем и составом из плана.
6. Нажмите «Сохранить выбор и скачать BAT». После обновления до 1.2.4 **скачайте новый BAT**, старый скрипт версии 1.2.3 делит пакет на дополнительные части.
7. Положите BAT рядом с full и запустите. Нужен Windows PowerShell 5.1 или новее; дополнительные архиваторы не нужны. Если full не найдена, скрипт попросит путь.
8. BAT соберёт по одному ZIP на выбранный пакет, без ограничений по фактическому весу и без перераспределения файлов. Например, четырём пакетам соответствуют ровно четыре ZIP mik-3-0001.zip … mik-3-0004.zip, даже если отдельные архивы больше 800 МБ.
9. Результат находится в новой папке `mik-packages-ID/build-дата-время-код`. Путь выводится в консоли. Внутри ZIP, upload-order.txt с порядком загрузки, missing-files.txt с ненайденными путями и replaced-files.txt с заменами расширений.
10. Загружайте ZIP из **новой папки** по списку. Доступны загрузка с компьютера и прямая ссылка. После приёма архива товары обрабатываются небольшими запросами без перезагрузки страницы. При паузе нажмите «Продолжить».

Плагин не отклоняет ZIP за превышение ориентировочного размера и не устанавливает прежний предел в 1 ГБ. С компьютера файл передаётся фрагментами до 1 МБ, поэтому upload_max_filesize не обязан вмещать весь ZIP. Реальные ограничения диска, файловой системы, временных файлов и хостинга сохраняются. Для CSV действует отдельный предел 100 МБ.

Размеры в таблице плана предварительные. BAT сохраняет точное число выбранных пакетов и все их ссылки на файлы. Общий физический файл внутри одного ZIP сохраняется один раз; файлы из разных пакетов между ними не переносятся. Если файл отсутствует во всех подходящих расширениях, он попадёт в missing-files.txt; товар может импортироваться с предупреждением об этом медиа.

## Обновление с версии 1.2.3

Выберите прежний импорт и скачайте новый BAT. CSV менять или пересчитывать план не нужно. Новый BAT создаёт целые ZIP с именами из плана. Если старые части уже загружены, но пакет ещё не обрабатывается, целый ZIP заменит этот незавершённый комплект. Для изменения файлов уже импортирующегося или завершённого пакета создайте новый план через «Пересчитать пакеты».

## Старый путь JPG, а файл переконвертирован

Если CSV содержит `search/img/part.jpg`, а в FULL есть `search/img/part.png`, BAT сначала проверит точный путь, затем JPG, JPEG, JPE, PNG, WebP, GIF, AVIF, BMP, DIB, TIF, TIFF, ICO, HEIC и HEIF в той же папке с тем же именем без расширения. Регистр расширения Windows не влияет на поиск. При нескольких вариантах действует указанный порядок. PDF остаются документами.

В ZIP сохраняется настоящее имя файла, а соответствие со старым путём записывается в манифест и replaced-files.txt. Импортёр определяет MIME по содержимому. BMP, TIFF, ICO и HEIC/HEIF преобразуются в PNG при поддержке исходного формата редактором изображений хостинга. Если поддержки нет, журнал показывает найденное имя и причину; такой файл можно заранее сохранить в JPG, PNG или WebP.

## Загрузка по ссылке

Нужна прямая публичная HTTP(S)-ссылка, по которой ZIP или CSV скачивается без входа в аккаунт. Страница просмотра облачного диска вместо файла будет отклонена. Сервер сайта скачивает файл сам. При поддержке HTTP Range источником скачивание идёт частями с сохранением прогресса. Без Range используется потоковое скачивание целого файла; при превышении времени запроса используйте загрузку с компьютера или другой источник с Range.

ZIP должен быть создан BAT выбранного импорта. Код и служебные файлы старого FULL в пакеты не включаются. SHA-256, пути, реальный тип медиа и принадлежность архивов импорту проверяются. Товары обновляются по legacy_id/SKU; файлы с одинаковым SHA повторно используются. Временные файлы должны сохраняться до завершения импорта.

## Пересчёт плана

Чтобы изменить предварительную разбивку, укажите новый ориентировочный размер и нажмите «Пересчитать пакеты». Создаётся отдельный план для всего того же CSV, все пакеты отмечены по умолчанию. Скачайте BAT нового плана и создайте его ZIP. Прежний план и уже созданные товары сохраняются.

## Формат каталога

UTF-8 с BOM, разделитель `;`, первая строка — технические имена колонок. Для файлов, массивов и характеристик используется JSON в CSV-ячейках.

- `legacy_id`, `sku`, `source_sku`, `name`, `category`, `brand`, `package`.
- `price_rub`, `price_wholesale`, `price_special`, `stock`, `stock_note`.
- `description`, `short_description`, `specs_json`.
- `images_json`, `pdfs_json`, `ozon_url`, `assets_json`, `source_url`.
- `new`, `featured`.

`assets_json` содержит объекты `{ "path": "search/img/...jpg", "size": 12345, "kind": "image" }`. Пути идут от корня full. `images_json` и `pdfs_json` перечисляют соответствующие пути. `specs_json` — массив `{ "label": "Напряжение", "value": "600", "unit": "В" }`; возможно поле `param_key` из справочника.

Базовая цена переносится в WooCommerce, оптовая — в группу МелкОпт (ID 3), спеццена сохраняется в метаполе `_mik_special_price` для последующей настройки коммерческих условий. Валютный прайс загружается отдельно; значения в долларах не вычисляются из рублёвых автоматически.

## Исходная выгрузка

`tools/prepare_catalog.py` читает XLSX, карту файлов и SQL как данные; SQL не выполняется. Скрипт не переносит клиентов, старые пароли, заказы или платёжные данные. Встроенные data URI извлекаются отдельно. Если основной путь отсутствует в карте, используется существующее изображение `d_` или `s_`. Все остальные отсутствующие пути перечислены в отчёте.

В некоторых исходных строках пустое наименование и нестандартно заполненные поля. Альтернативное имя используется с новым техническим SKU `legacy-ID`; исходные цены и остатки сохраняются, а такие строки перечисляются в `source-field-notes.json`. Их следует просмотреть перед продажами. Это исправление структуры, без догадок о правильной цене.

Подготовленные данные поставляются отдельным архивом здесь, а исходный код находится в GitHub. FULL не скачивался и не включался в плагин.
