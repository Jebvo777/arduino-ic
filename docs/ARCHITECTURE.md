# Архитектура MIK Shop

Товары, категории, изображения, SKU и основной остаток — WooCommerce. Покупатели не являются пользователями WordPress. Пароли хешируются WordPress Password API; собственные сессии используют случайный HttpOnly cookie, CSRF и ограничение попыток входа. Администраторы входят обычным способом WordPress и используют право manage_woocommerce.

Собственные таблицы: покупатели, сессии, корзина/избранное, группы/цены, заказы/строки, остатки, движения, параметры товаров, импорт/строки/пакеты, ограничения запросов. Групповые цены выдаются только сервером для текущей сессии. Ответы с покупательскими данными не кешируются.

Заказ резервирует остатки атомарно в транзакции; повтор отправки с тем же ключом не создаёт второй заказ. Отмена возвращает остаток один раз. WooCommerce используется для каталога, без WC_Cart, WC_Checkout и WC_Customer.

Импорт: чистый UTF-8 CSV → разбор короткими запросами → план пакетов по МБ → выбор пакетов → BAT с PowerShell и встроенным планом → локальные ZIP → загрузка кусками → импорт короткими запросами с сохранением прогресса. Пакеты независимы: общие файлы могут повторяться. На сервере пути проверяются; исполняемые файлы и переходы за пределы каталога запрещены. Ошибки строки доступны в журнале; повтор обновляет товар по legacy_id/SKU.

Т-Банк и СДЭК являются явными заглушками по текущему запросу. Самовывоз доступен и настраивается. Прямые ссылки Ozon сохраняются из товарных данных, иначе используется поиск по имени товара. Приоритет текущего запроса выше предыдущего ТЗ.

Стили ограничены .mik, .mik-admin и собственными переменными, не изменяют оформление темы. Контент, страницы, слайды, контакты, группы, поля и параметры доступны в админке.
